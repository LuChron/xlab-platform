# X-Lab 平台产品与链上设计

> 状态：已按当前实现校准（2026-10-24）。

## 结论

设备借用和空间入驻适合放在同一个 Fabric 网络与通道中，但不应混成一套表或一个页面。它们共享项目、人员、审批与审计语义，同时具有不同的状态机和前端任务。

```text
项目申请  ──获批──> 空间分配 ──确认──> 入驻项目
                                      │
                                      └──项目编号──> 设备申请 ──交接──> 归还验收
```

## 为什么是一条链

- 项目是资源使用的共同主体，空间和设备都可以关联同一个项目编号。
- 项目退出时需要释放空间，并核对未归还设备。
- 管理员、项目负责人和资源保管人需要共享可追溯记录。
- 第一版没有账本级隔离需求，拆成多个通道只会增加部署和查询复杂度。

技术实现采用一个链码中的多个对象前缀：`EQUIPMENT:`、`SPACE:`、`PROJECT:`、`BORROW:`、`APPLICATION:`和 `ALLOCATION:`。对象不会混淆，但可以在同一笔业务校验中关联。

## 前端信息架构

### 入口一 设备协作

- 设备浏览与筛选
- 设备详情与当前位置
- 借用申请
- 管理员审批与领取交接
- 归还申请与验收
- 单件设备责任时间线

### 入口二 项目入驻与空间

- idea 入驻申请
- 团队与阶段目标
- 简化楼层图
- 工位与功能区选择
- 入驻周期与冲突检查
- 成果提交、续期和退出

### 统一项目视图

项目详情页汇总项目成员、已分配空间、当前借用设备、阶段目标和待办事项。它是两个入口的联动点，不替代两个独立入口。

## 视觉方向

主题取自未来学习中心的“工作站、工程实践、共同创造”。界面使用偏蓝图的网格结构，不使用通用管理后台的纯白表格模板。

- 深墨蓝 `#0B1F33`：导航与技术底色。
- 浙大蓝 `#1D5C9B`：主操作和空间入口。
- 实验青 `#24A89A`：可借、可用和确认状态。
- 工程橙 `#EE9B52`：待处理、借出和阶段节点。
- 纸面白 `#F4F7F6`：主要背景。
- 信号红 `#C84B4B`：冲突、逾期和异常。

标志性元素是“资源地图”：空间入口展示可点击的平面图，设备入口使用与平面图一致的位置编码，让用户能从设备卡片直接理解设备在哪个区域。

## 当前状态机

### 设备

```text
AVAILABLE -> REQUESTED -> APPROVED -> BORROWED
BORROWED -> RETURN_REQUESTED -> RETURNED
RETURN_REQUESTED -> EXCEPTION -> RESOLVED
```

异常单变为 `RESOLVED` 时，设备状态恢复为 `AVAILABLE`。

### 项目入驻

```text
Application: SUBMITTED -> APPROVED -> ACTIVATED
Application: SUBMITTED -> REJECTED
Project: ACTIVE -> CLOSED
Project: 续期后仍保持 ACTIVE，并累加 extensions
```

### 空间

空间本身保持 `OPEN` 或 `MAINTENANCE`。占用状态通过带起止日期的 `SpaceAllocation` 计算，避免把未来安排覆盖成一个简单布尔值。

## 当前数据边界

链上保存：

- 设备、空间和项目稳定编号。
- 申请、审批、交接和验收状态。
- 项目与设备、空间的关联。
- 项目说明、借用用途、内容摘要、操作者身份和交易时间。
- 状态变更历史。

链下当前只保存进程内登录会话和前端搜索状态。设备照片、交接照片和成果文件的
对象存储尚未接入，相关字段只作为引用或摘要预留。

## 本次实现范围

1. 设备借用必须关联已入驻项目，不开放个人无项目借用。
2. 空间模块处理项目周期内的工位与功能区分配，不做小时级会议室预约。
3. 演示账本包含 28 台示例设备；型号与资产编号用于课程演示，不代表实际采购台账。
4. 资源地图包含 3F / 4F 共 18 个空间单元，并按起止日期检测分配冲突。
5. Org1 负责项目评审、空间分配、设备审批和交接确认；Org2 负责提交申请、成果与归还请求。
6. 团队账号绑定项目和借用单，不允许跨团队修改成果或操作借用单。
7. 空间分配需同时通过日期冲突和容量校验；未处理的设备异常会阻止结项。
