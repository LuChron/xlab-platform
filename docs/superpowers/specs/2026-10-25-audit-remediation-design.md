# X-Lab 审查问题修复设计

## 目标

修复审查报告确认的账本初始化、对象归属、异常结项、Fabric 身份回退、空间容量、申请正文表述、部署重置和活动排序问题，同时保持 demo 与 Fabric 两种模式的业务规则一致。

## 范围

- 管理操作继续由 Org1 执行，团队申请、成果、借用和归还改为仅允许 Org2。
- HTTP 层以登录账号的 `teamId` 判断项目与借用单归属；负责人和借用人标识由后端写入，不接受表单冒充。
- 链码以 Fabric `clientID` 保存并校验项目所有者和借用人身份。当前 demo 只有一个团队账号；生产环境若增加团队账号，需要为不同团队配置不同的 Fabric 身份。
- 未处理的 `EXCEPTION` 借用单计入未结清设备，阻止项目结项。
- 项目激活时，所选空间总容量必须不少于申请工位数，并拒绝重复空间编号。
- `InitLedger` 仅允许 Org1，且已有初始化标记或预置键时拒绝再次写入。
- Fabric 组织连接失败必须向请求返回错误，不允许回退为原组织签名。处理器使用请求局部 Store，连接缓存使用共享锁。
- 页面只有一段“项目说明”；系统保存该说明及其哈希。移除未落地的独立 `ideaText`，文档不再声称正文已保存到链下。
- `deploy/up.sh up` 不再先清除网络；显式 `reset` 才执行清理。
- 活动流水按 RFC3339 时间倒序排列，TxID 作为稳定的次级排序键，再截取 200 条。

## 不在本次范围

- 不搭建学校统一身份认证、Fabric CA 注册流程或对象存储。
- 不代填成员姓名、贡献分，不虚构 PPT 成品或视频配音。
- 不增加新页面，也不改变现有视觉设计。

## 方案比较

1. 仅在前端隐藏不允许的操作：改动小，但直接调用 HTTP 或链码仍可越权，不采用。
2. 后端账号归属加链码证书归属：能覆盖 demo 与 Fabric 两种模式，改动集中，可通过自动化测试验证，采用。
3. 每个成员独立 CA 注册并接入链下数据库：更接近生产系统，但明显超出当前原型和提交周期，不采用。

## 兼容与迁移

新增字段对 JSON 反序列化向后兼容，但旧链上项目没有 `ownerIdentity`，无法通过新的团队写操作校验。部署最终版时应使用显式 `./deploy/up.sh reset` 重建测试账本；普通 `up` 不再删除已有账本。

## 验收

- Org2 不能调用 `InitLedger`，且初始化不可重复。
- 非项目所属团队不能提交成果或借用设备，非借用人不能发起归还。
- `EXCEPTION` 未解决时结项失败，解决后可结项。
- 申请 99 个工位但只分配容量 2 的空间时失败。
- Org2 Gateway 连接失败时请求失败，不产生 Org1 代签交易。
- 活动流水按时间倒序，超过 200 条时保留最新记录。
- `go test`、前端构建、脚本语法和仓库检查全部通过。
