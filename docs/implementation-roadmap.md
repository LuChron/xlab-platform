# X-Lab 大作业实施路线

> 状态：核心功能已完成。本文件保留实施顺序和验收范围，当前运行说明以根目录 `README.md` 为准。

## 总体目标

最终交付一个可在浏览器中完整演示的 B/S 系统：项目团队申请入驻未来学习中心，管理员评审并分配空间，获批项目再申请设备，保管人完成领取和归还验收，所有关键状态变更由 Fabric 留痕。

## 为什么适合本课程

- 实用性：对应 X-Lab 现有的空间管理、设备管理和项目制运作。
- 完整性：有前端、后端、链码、身份、审批、交接、查询和历史。
- 创新性：不只是设备借还，而是用项目编号联动空间、设备和阶段成果。
- 美观性：双入口和资源地图能形成清晰的答辩演示路径。

## 系统分层

```text
浏览器
  ├─ 设备协作入口
  └─ 项目入驻与空间入口
         ↓ REST API
Go 后端
├─ 业务校验与登录会话
  └─ Fabric Gateway
         ↓
Fabric test-network / xlab channel / xlab chaincode
  ├─ ProjectApplication + Project + SpaceAllocation
  └─ Equipment + BorrowRecord + History
```

## 实施记录

### 阶段一 锁定数据和规则

1. 构造 28 台演示设备清单，包含资产编号、名称、类别、位置、附件、保管人和状态。
2. 将空间范围确定为项目周期内的工位和功能区分配，不加入小时级预约。
3. 将项目评审、设备审批、领取和归还确认归入 Org1 管理职责。
4. 设备借用必须关联已入驻项目。

### 阶段二 打通 Fabric

1. 复用 `hw6` 的 Fabric test-network 和链码部署流程。
2. 复用 `hw7/SDK` 的 Gateway、gRPC 和 TLS 连接配置。
3. 部署 `chaincode/`，调用 `InitLedger`。
4. 将 `backend/` 内存 Store 替换为 Gateway 适配器，保持已有 REST API 不变。
5. 增加两个链上身份：X-Lab 管理员和项目成员；有余力再增加设备保管人。

### 阶段三 补齐完整流程

1. 项目：提交、评审、激活、续期、退出。
2. 空间：日期冲突检查、分配、释放。
3. 设备：申请、审批、领取、归还申请、验收、异常。
4. 项目退出前校验“无未归还设备”，然后释放空间。
5. 在页面中增加单个设备和单个项目的链上历史时间线。

### 阶段四 测试与答辩

1. 后端加入种子数据与演示鉴权测试，提交前由 `deploy/check.sh` 统一执行。
2. GitHub Actions 自动检查后端、链码、前端构建和 Shell 脚本语法。
3. 保留一键演示数据和内存兜底模式，避免答辩现场受容器环境影响。
4. 已录制 7 分钟内的展示视频，并保留关键步骤静帧；界面变更后需重新录制最终版。

## 最小可交付范围

时间紧时，保证以下内容真正可用：

- 一个可运行的 Fabric 网络和一份可部署链码。
- 项目入驻、设备借还两条闭环。
- 前端双入口、资源状态、审批操作和历史查询。
- 四个角色中至少真正区分管理员与普通成员。
- 源代码、项目介绍文档、答辩 PPT、演示视频和组员分工表。

## 答辩演示剧本

1. 40 秒：说明 X-Lab 资源协作的现实问题以及为什么需要可追溯记录。
2. 50 秒：展示系统架构和“一条链、两个入口”。
3. 100 秒：申请项目入驻，展示空间选择和日期冲突。
4. 100 秒：关联已入驻项目借用设备，完成审批和领取。
5. 70 秒：完成归还验收，查看区块高度、交易 ID 和状态历史。
6. 40 秒：总结项目价值、当前数据边界和后续可扩展点。
