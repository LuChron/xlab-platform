# 答辩演示骨架（7 分钟 + 3 分钟提问）

> 对应评分维度：美观性 20 / 实用度 30 / 完整性 30 / 创新性 20

## 演示前准备（演示视频同此脚本）

1. `./deploy/up.sh` + `./deploy/run.sh fabric`，确认 `/api/health` 返回 `mode: fabric`
2. 浏览器开两个窗口：admin 登录（委员会）、team 登录（项目团队）
3. 演示账本已有：1 个在驻项目、1 个待评审申请、3 笔借用记录（1 已还、1 在借、1 待批）

## 3 分钟提问预案

**Q1 为什么不用普通数据库？**
这个场景需要区分管理方与项目团队发起的交易，并对状态流转做统一约束。
Fabric 在原型中提供 MSP 身份、交易 ID、区块历史和链码校验。当前演示后端为了本地运行
统一加载两组测试证书；生产部署仍需要由各组织分开托管私钥和 Gateway。

**Q2 为什么一条链而不是两条？**
项目是空间与设备的共同主体；项目退出时要同时释放空间并核对设备，必须在一个
账本里做跨对象校验。一个通道两个业务模块足够，拆两条链只增加部署与查询复杂度。

**Q3 链上存了什么，链下存了什么？**
当前链上保存项目说明、借用用途、业务状态、内容摘要、操作身份和时间戳。
照片和成果文件的对象存储尚未实现，原型只预留引用与摘要字段，不把规划中的能力当作已交付功能。

**Q4 怎么保证同一设备不被重复借出？**
链码校验设备状态必须为 AVAILABLE；并发交易在区块验证阶段会检查同一设备键的
MVCC 版本，冲突交易会被标记无效，因此只有一个写入能够生效。

**Q5 工位冲突怎么判断？**
按 SpaceAllocation 起止日期做区间相交（start < otherEnd && end > otherStart），
而不是压成"占用/空闲"布尔值，因此支持未来排期。演示里分配同一工位会被拒。

**Q6 权限是怎么实现的？页面切身份是不是只是前端把戏？**
不是。链码读 `ctx.GetClientIdentity().GetMSPID()`，写操作按组织白名单校验；
后端按登录用户的组织用对应证书签名。现场可以用 `peer chaincode invoke` 以
Org2 身份直接调管理员函数，链码照样拒绝。

**Q7 和 fabcar 有什么区别？**
fabcar 是单合约 CRUD 示例。本项目有多组织权限、双业务状态机、跨模块引用完整性
校验（结项必须归清设备）、审计流水、按组织签名与两层权限拦截。

**Q8 为什么用 CCAAS 而不是常规链码部署？**
本机 Docker 29.x 最低支持 API 1.44，Fabric peer 内置的旧 Docker client 用 1.41，
构建链码时报 broken pipe。CCAAS 让链码作为独立服务运行、peer 只连接，绕开该问题，
同时链码构建不受 ccenv 内 Go 版本限制。

## 一句话总结（备用收尾）

「我们用一个项目编号联动空间和设备：管理方与项目团队的操作按组织身份留痕，
链码统一校验状态和归属——设备没还清或异常没处理，项目就不能结项。」
